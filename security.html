Security & research.

Practical security engineering for the software we build and operate.

MAU Properties LLC brings together real estate and digital ventures. Our internal security focus supports that software portfolio: understanding risk, validating findings, and improving the systems behind our projects.

A defined scope.

Security research is limited to our own software, infrastructure, and controlled test environments, or systems covered by explicit written authorization. The purpose is to find, understand, and remediate weaknesses.

Hankins.work presents our security and AI work. Veyra is a private security-operations platform in development. SickDocs and Plumbline are practical software projects in our portfolio.

Client security services are not currently offered.

Planned AI-assisted workflows.

  • Secure code & application review

    Review owned source code, authentication, authorization, API boundaries, and data handling. Turn findings into actionable fixes and regression checks.

  • Controlled vulnerability validation

    Reproduce suspected weaknesses in authorized lab or staging environments, document the evidence, and validate remediation.

  • AI integration security

    Evaluate prompt-injection exposure, tool permissions, and trust boundaries in our own AI-enabled workflows.

  • Defensive security operations

    Explore vulnerability triage, detection engineering, and the context needed to make security findings useful to engineers and leadership.

Research principles.

  • Establish authorization. Define the assets, permitted activity, and stopping conditions before testing.
  • Keep test data appropriate. Use synthetic or redacted material for security reproductions and minimize sensitive data shared with tools.
  • Validate with human review. Check AI-generated findings against evidence and review changes before they reach production.
  • Keep access internal. Restricted security tooling is intended for approved internal research and engineering, not resale, public model access, or downstream customer requests.
  • Document the outcome. Record findings, remediation, and validation so work can be reviewed and repeated.
